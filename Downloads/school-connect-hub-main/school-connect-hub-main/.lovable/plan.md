## Корінь проблеми (важливо!)

Знайшов справжню причину всіх багів. У проєкті зараз **два різні Supabase-проєкти**, і застосунок працює не з тим, з яким працюю я:

- **Старий Supabase** (`bmvqbxqsyuratutvolwd.supabase.co`) — саме сюди йдуть запити з вашого сайту (це видно у мережевих логах: запит на завантаження ZIP-у йде туди й повертає `404 Bucket not found`). Тут авторизуються користувачі, тут зберігаються старі дані.
- **Новий Lovable Cloud** (`iudwxuyipxioeluljznk.supabase.co`) — сюди я застосовував усі останні міграції (бакет `templates-code`, колонки в `sites`, политики RLS тощо). Тому виправлення «не доходять» до сайту — вони в іншій базі.

Через це:

- Бакет `templates-code` існує лише в новій базі → старий сайт каже «Bucket not found».
- Зміни ролей/RLS, нові колонки сайтів, нові політики — теж є тільки в новій базі.
- Я **не маю прямого доступу до старого Supabase** через інструменти Lovable Cloud — туди можу писати лише ви через його власну панель.

## Що треба вирішити

Треба обрати один із двох шляхів — без цього виправляти баги «по одному» немає сенсу, бо вони будуть повертатись.

### Варіант A (рекомендований) — повністю перейти на Lovable Cloud

1. Я переконуюсь, що `src/integrations/supabase/client.ts` зчитує `VITE_SUPABASE_URL` з `.env` (новий проєкт) — і перезапускаю dev-сервер, щоб preview почав ходити в нову базу.
2. Налаштовую Google OAuth у новому Cloud-проєкті (без цього вхід через Google зламається).
3. Експортуємо дані зі старого Supabase (users, profiles, sites, templates, classes, lobbies, messages, news, homework, lessons, grades) у CSV і я імпортую їх у новий.
4. Перевіряю Шаблон (upload у `templates-code`), публікацію сайту, адмін-функції — все має запрацювати з першого разу.
5. Старий Supabase-проєкт можна відключити.

### Варіант B — лишитись на старому Supabase

Тоді мені треба, щоб ви відкрили старий Supabase Dashboard і виконали там вручну (я підготую SQL/інструкції):

- створити бакет `templates-code` (public);
- додати колонки до `sites` (`description`, `keywords`, `og_image`, `published`);
- додати GRANT та RLS-політики для `templates`, `sites`, `user_roles`;
- застосувати функції `update_user_role`, `get_admin_users`, `has_role`.

Усі майбутні зміни БД треба буде так само руками переносити, бо мої інструменти туди не дотягуються.

## Про «перенести інформацію в GitHub»

Це робиться через UI Lovable, а не кодом: меню `+` (внизу зліва в чаті) → **GitHub → Connect project** → авторизувати Lovable GitHub App → створити репозиторій. Після цього код синхронізується автоматично в обидва боки. **Дані з бази** експортуються окремо: Cloud → Database → Tables → кнопка експорту в CSV для кожної таблиці.
